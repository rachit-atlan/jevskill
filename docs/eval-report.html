Summary

On the 20 tasks where an installed skill materially changes the output, jev pointer routing passed 82.5% against native's 72.5%, scored 0.950 against 0.899, and cut context per call by 22%. Native picked the right skill 87.5% of the time and skipped it on 10% of trials; jev skipped none and misrouted 5%, all on skills whose descriptions read as review-only. Left to itself with jev as an MCP tool, the agent called the router on 0% of trials; one system-prompt line raised that to 86.4%.

What this does not show. Everything ran at 61 skills. The claim that jev matters more at 100+ skills is untested here. Sample is 20 tasks × 2 trials for the primary arms; the pass-rate gap between jev pointer and native is 4 trials of 40. Robustness arms (native with full descriptions, jev body, jev MCP unprompted) ran one trial each. 2 tasks failed in every arm and are excluded as uninformative: k-pdf-report, k-wir-signin.

Why this eval

Claude Code lists every enabled skill's description in the system prompt and lets the model decide whether to call one. That costs context on every turn, and it relies on the model choosing to reach for a skill. jev is a decision model: given text and a fixed set of options, it returns a probability distribution in about 350 ms for a fraction of a cent. The question was not "is jev a better classifier than Claude" but "if the harness routes with jev instead of leaving it to the model, do tasks come out better, cheaper, or both?"

Two earlier framings were rejected. A pure router-versus-router comparison is unfair to native, because a capable model that skips a skill it does not need has not misrouted. So task quality is the verdict and routing accuracy is the diagnostic. And an easy task set is useless: on the first pilot every arm scored 0.99 because the model already knew TanStack and Vite. This run keeps only tasks that fail when no skill is available.

Why jev is needed for skill routing

  1. Native skips skills. On house-specific prompts native routed well (87.5%) but still skipped the applicable skill on 10% of trials; on an earlier generic pilot set it skipped 3 of 4. Skipped trials fail the task. jev acting through a hook removes that decision.
  2. The native listing is capped. Claude Code truncates the skill listing at roughly 15k characters. With 63 skills present, 49 appeared as bare names, in alphabetical order, so which skills keep a description is an accident of naming. jev sees every description, up to 255 options.
  3. It is cheap enough to run on every prompt. jev cost for all 228 trials in this run: $0.027. Latency 380 ms p50 inside the hook cold, about 430 ms with the warm-connection daemon.
  4. Pointer injection keeps the saving. Injecting one line that names the skill and its path scored the same as injecting the full body, at the lowest context of any arm. The model reads the file when it wants it.

What the run taught us beyond the headline

  • Injected guidance is not compliance. With a skill injected in full, the model wrote that it "intentionally" ignored it because the skill required React canary and the seeded project pinned stable React. Native made the same call. Once the seed matched the skill, 11 of 12 skill-arm trials passed. A skill whose prerequisites conflict with the repo gets set aside, however it arrived.
  • Misroutes are description bugs. Both landing-page trials went to frontend-patterns because frontend-taste describes itself as a post-generation review. Appending one sentence flips both prompts to taste at 0.87 and 0.71 in an offline probe. The eval can now test a description change in both arms before the skill owner ships it.
  • The graders caught themselves. A jq scoping bug failed one task in every arm identically; six noise skills overlapped real prompts; the judge needed four turns. All found by reading transcripts, all fixed before this report.
  • Bypassed permissions are a real hazard. A no-skill trial wrote into the author's actual Obsidian vault because the prompt said "in my vault". Writes outside the workspace are now a reported metric.

Runs were recorded against a local agent-gateway (just dev), onboarded as a dev user. Two comparison groups exist: knowledge (pre-fix lineage) and knowledge-v2 (this report). Registry summaries matched the local report to three decimals.

SDK gaps found on the way (full notes in docs/sdk-gaps.md): the trace read-back gate cannot pass on a local gateway with no trace store and the error blames ingestion lag; resume rejects a config mismatch without naming the key; no helper to abandon a stranded running experiment; dataset-backed Eval has no case filter; Claude Code is untraced; onboarding is undocumented from the SDK side.

Limits and next

  • 20 tasks, 2 trials, one model. Prompts and gold labels authored inside the project; two misrouted, so they are not tuned to jev, but an outside author would be stronger.
  • Native as shipped saw most skills as bare names. The descriptions-visible variant behaved identically on the pilot but has not run on this set.
  • Single-turn prompts. The hook sees one prompt; native sees the conversation.
  • Next: descriptions-visible native on this set; a third trial; a universe-size sweep at 100 and 200 skills for the scale claim; multi-turn tasks with recent history passed to jev as state.
